# Массажный салон «Лавелия» — Алматы

Готовый многостраничный сайт: 13 страниц, мобильная навигация, запись через WhatsApp и выбор маршрута в Яндекс Картах или 2ГИС. Работает на GitHub Pages, отдельный сервер и база данных не нужны.

## Админка GitHub Pages

- Сайт: https://swvalera.github.io/massazhny-salon/
- Админка: https://swvalera.github.io/massazhny-salon/admin/

Админка меняет независимые цены восьми услуг, телефон, адрес и точку маршрута. Настройки сохраняются в `data/defaults.json` ветки `codex/laveliya-site`. GitHub Actions собирает все страницы из этих данных и публикует их на Pages. Цена меняется одновременно в карточках, прайс-листе, на странице услуги и в её SEO-разметке. Обычно публикация занимает несколько минут. Админка отдельно показывает факт сохранения и подтверждение публикации по `deployment.json`.

Для входа создайте [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new) в аккаунте владельца сайта. Укажите понятное имя и срок действия, Repository access → Only select repositories → `massazhny-salon`, Permissions → Contents → Read and write. Скопируйте ключ в менеджер паролей и вставьте его в поле входа. Инструкция также доступна на экране входа.

Ключ отправляется только на `api.github.com`, хранится только в памяти текущей вкладки, не записывается в репозиторий, localStorage или cookies. После перезагрузки страницы нужно войти заново. При выходе ключ удаляется из памяти приложения. Ключ нельзя давать посетителям сайта; для другого администратора нужен аккаунт с доступом к репозиторию и свой ключ.

При одновременном редактировании проверяется версия файла: чужое сохранение не перезаписывается автоматически. При сетевом сбое записи админка предлагает перечитать данные. Сохранения запускают GitHub Actions и зависят от доступности GitHub и успешной сборки. Если публикация не подтвердилась, откройте её ход по ссылке в админке.

Собственный домен для работы админки не нужен. При смене домена потребуется обновить базовый путь сборки и настройки публикации. Содержимое `data/defaults.json` публично: там только цены и контакты салона, никаких секретов или данных клиентов.

## Необязательная версия Cloudflare

В репозитории сохранён альтернативный Worker с D1 и входом по паролю. Инструкция: [CLOUDFLARE.md](CLOUDFLARE.md). Его локальная база и `/admin/` на порту 4174 независимы от действующего сайта GitHub Pages. Для текущей публикации Cloudflare не используется.

## Предварительный просмотр

Код хранится в репозитории `SWValera/massazhny-salon`. Рабочая ветка — `codex/laveliya-site`. Домен пока не подключён. HTML находится в `dist/`, исходники — в этой папке. Временная ссылка для телефона создаётся Cloudflare Quick Tunnel и доступна любому, кто знает ссылку. Она работает, пока компьютер не спит и запущены сервер и туннель. После перезапуска туннеля ссылка меняется.

Публичный просмотр: https://swvalera.github.io/massazhny-salon/

GitHub Actions автоматически обновляет его после изменений в `codex/laveliya-site`. Админка сохраняет настройки через GitHub API; данные D1 здесь не используются.

На этом компьютере: http://localhost:4173/

Для локального просмотра с телефона используйте адрес компьютера в той же Wi-Fi сети и порт 4173.

После остановки текущего просмотра запустите двойным щелчком `Просмотр сайта.command` либо выполните:

```sh
python3 scripts/preview.py
```

Терминал покажет новую ссылку `https://…trycloudflare.com`. Оставьте окно открытым. `Ctrl+C` завершит просмотр. Если порт занят, уже запущенный просмотр нужно сначала остановить.

Туннель передаёт только папку готового сайта `dist/`, не исходники и не другие файлы компьютера. Черновик закрыт от поисковиков через `noindex`, `robots.txt` и HTTP-заголовок. Это не парольная защита.

## Редактирование

- `data/defaults.json` — единый источник цен и контактов для GitHub Pages.
- `scripts/build.py` — тексты и структура; `scripts/templates.py` — шаблоны; `scripts/render_pages.mjs` — подстановка актуальных настроек; `scripts/build_pages.py` — полная сборка Pages.
- `admin/pages-admin.js`, `admin/github-client.js` — интерфейс GitHub Pages и безопасная работа с GitHub API. `admin/admin.js` — альтернативный интерфейс Worker.
- `cloudflare/worker.js` — авторизация, сохранение и выдача страниц; `cloudflare/render.js` — валидация и подстановка данных.
- `admin/` — интерфейс администратора; `migrations/` — схема D1 и начальные значения.
- `assets/site.css` — сетка и адаптация для телефона; `assets/brand.css` — палитра #C8BED8 / #F4B5CD / #FCFAFD и оформление всех блоков.
- `assets/site.js` — меню, окно записи, выбор услуги, выбор карт и кнопка «Назад».
- `assets/` — локальные изображения и шрифты.

После правок:

```sh
python3 scripts/build_pages.py
npm test
```

Обновите страницу в браузере. Повторно запускать сервер и туннель не нужно.

Запись не имитирует отправку заявки: посетитель выбирает услугу, открывает WhatsApp и сам отправляет сообщение мастеру. Дата и стоимость подтверждаются лично. Сайт не хранит персональные данные и не использует аналитику. Встроенной карты нет: внешние карты открываются только по выбору посетителя.

## SEO и окончательный запуск

Все страницы содержат готовый HTML, уникальные title/description, один H1, внутренние ссылки, alt у изображений, семантические разделы и JSON-LD для местного бизнеса. Страницы массажа дополнительно содержат разметку услуг. Шрифты загружаются локально в WOFF2, изображения имеют уменьшенные версии для телефона, нижние фотографии загружаются отложенно.

Когда будет выбран настоящий HTTPS-домен:

```sh
python3 scripts/build.py --production --site-url https://YOUR-DOMAIN
python3 scripts/check.py
```

Команда включит индексацию, создаст абсолютные canonical/og:url и `sitemap.xml` с фотографиями, добавит структурированные хлебные крошки, обновит `robots.txt`. Домен не зашит в исходники. Проверяйте production-сборку на обычном хостинге: `scripts/serve.py` всегда отдаёт noindex, потому что предназначен для черновиков.

Текущая сборка Pages использует `scripts/build_pages.py --base-path /massazhny-salon`. Команда production выше относится к исходной статической сборке; для запуска Pages на собственном домене нужно отдельно настроить корневой базовый путь, подстановку `data/defaults.json` и SEO в сборке Pages. До этого текущий просмотр остаётся закрытым от индексации.

Перед публичным запуском желательно дополнить факты: график, этаж/кабинет и вход, длительность сеансов и точные цены по зонам, подтверждённые сведения о мастере. Дипломы, отзывы, стаж и медицинские обещания не выдуманы. На странице лечебного массажа указано, что процедура не заменяет консультацию врача.

После запуска: подтвердить сайт в Google Search Console и Яндекс Вебмастере, отправить sitemap, оформить/уточнить карточки бизнеса в Google, Яндекс Картах и 2ГИС. Техническая подготовка не гарантирует сроков индексации или позиций в поиске.
